# Market pilot status — 2026-11-12

Local implementation, not a completed mainnet market. Invited testers: the owner and one second tester (IDs kept in the private server config). Public wallet associations: tor.nuvelorian.near (smith), grym.nuvelorian.near (hunter). Both accounts exist and are registered on pl4.nearlytrade.near. Wallet checks are read-only; game balances are simulated and are not credited from these wallets.

Approved pilot settings: seller fee 5%; intended mainnet recipient nuvelorian.near; maximum combined pilot budget equivalent to USD 5, not USD 5 per agent. Local replacement-spending limit is pinned to the quote when initialized and stored alongside its baseline spend; changing the exchange rate does not expand that saved limit. Simulated fees currently remain inside the simulated treasury; no fee transfer to mainnet is implemented.

Replacement-only procurement is implemented: only new completed retail sales by agents issue a single-use entitlement. Old simulation sales do not retroactively fund procurement. Exact item ID and enhancement must match. A replacement may cost at most 80% of the original sale's net proceeds after fee, must also pass the existing price, seller, inventory and daily-budget limits, and the combined agent stock is capped at two copies per class. Entitlement consumption, escrow, money, receipts and journal are saved together; failed persistence consumes nothing. Agent-origin items retain a permanent no-buyback marker through player resale. Known shared buyer/seller identities cannot fund self-replacement. Unknown collusion remains possible but procurement payments are bounded below the retail spend funding them. Catalog-ID inventory still prevents holding duplicate catalog IDs in one account.

NEAR AI Cloud key verified without exposing it. Qwen/Qwen3.6-35B-A3B-FP8 returned valid decision JSON. Local runtime uses JSON mode and disables thinking for this model; bounded candidate actions are rechecked inside the settlement lock. At most 12 cloud requests per process per UTC day are configured, with at least a minute between requests for each agent. Restart resets this in-process inference counter; the provider API-key spending limit is the persistent cost guard. Cloud failure falls back to validated rules. No chain signing is given to the model.

Verification: test:market covers ordinary escrow/replay, wallet checks, access, exact FT receipts, replacement eligibility, 1000 zero-demand farm listings, linked identity/provenance, failed storage, a two-agent budget race and restart. demo:market performs a retail sale, one replacement, daily seller block and no-buyback through another player, conserving simulated funds. No live PL4 market payment, agent payout or withdrawal has been performed.

Still required before real-asset pilot: authentic deployed access for the two testers, durable mainnet payment settlement with verified receipts and item binding, fee payout/refund recovery, least-privilege agent signing, and a fixed atomic-unit funding allocation. The existing testnet manual three-transfer rehearsal is not an atomic mainnet escrow contract. Do not fund agent PL4 wallets expecting the current simulation to spend those funds. No deployment or public announcement in this work.
